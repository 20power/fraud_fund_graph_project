# 基于资金图谱的涉诈账户发现系统——部署与使用手册

> 适用版本：v0.2.0  
> 适用对象：甲方项目负责人、业务研判人员、系统管理员及首次接触本项目的使用人员  
> 推荐环境：Windows 10/11、64 位、CPU、Python 3.11 及以上版本

## 1. 文档目的

本手册用于指导首次接触本项目的人员完成以下工作：

1. 确认交付文件是否完整；
2. 在 Windows 电脑上安装运行环境；
3. 启动交互式研判系统；
4. 理解和使用六个业务页面；
5. 使用新数据重新运行完整分析流程；
6. 查看风险账户、可疑路径、典型案例及项目报告；
7. 组织甲方关联链路人工盲审；
8. 执行自动测试和交付完整性检查；
9. 处理常见部署与运行问题。

如果只需要查看已经生成的结果，完成“快速启动”即可，无须重新训练模型。

## 2. 系统定位与使用边界

本系统是基于甲方提供数据构建的本地辅助研判原型，主要用于：

- 对全量账户进行风险排序；
- 查看账户的主要风险因素；
- 查看账户之间的资金图谱；
- 检索一至三跳可疑资金路径；
- 查看五个典型案例的研判材料；
- 查看模型指标、提升口径和稳健性实验；
- 支持甲方对关联链路进行独立人工评价。

系统输出是风险线索，不是涉诈认定。任何账户处置、业务拦截或案件结论都必须由有权限的人员结合身份资料、业务背景、交易凭证和案件证据作出。

## 3. 交付包结构要求

项目采用单文件夹自包含结构。可以移动整个项目文件夹，但不要破坏内部相对目录：

```text
fraud_fund_graph_project\
   ├─ app.py
   ├─ README.md
   ├─ readme.txt
   ├─ run_app.bat
   ├─ requirements.txt
   ├─ environment.yml
   ├─ configs\
   ├─ data\
   │  └─ raw\
   │     ├─ 账户表.xlsx
   │     ├─ 交易边表.xlsx
   │     ├─ 风险标签表.xlsx
   │     └─ 说明.txt
   ├─ models\
   ├─ outputs\
   ├─ reports\
   ├─ scripts\
   └─ ...
```

默认配置使用 `data/raw` 中的四个甲方原始文件。所有执行路径均相对于项目根目录解析，项目移动到甲方其他磁盘或目录后无需修改绝对路径。如果文件名称或内部相对位置发生变化，才需要同步修改 `configs/data_config.yaml` 中的 `paths`。

### 3.1 必须保留的文件

至少应确认以下文件或目录存在：

| 文件或目录 | 用途 |
|---|---|
| `app.py` | 交互式界面入口。 |
| `run_app.bat` | Windows 快速启动脚本。 |
| `requirements.txt` | Python 依赖清单。 |
| `environment.yml` | Conda 环境定义。 |
| `configs/` | 数据路径、特征、模型、图谱和验收配置。 |
| `models/final/` | 已训练的正式模型。 |
| `data/processed/` | 已生成的特征和界面数据。 |
| `data/raw/` | 原始账户、交易、标签和说明文件。 |
| `outputs/` | 风险排名、路径、案例、图和实验结果。 |
| `scripts/verify_delivery.py` | 交付完整性检查入口。 |

## 4. 运行电脑要求

### 4.1 推荐配置

| 项目 | 推荐要求 |
|---|---|
| 操作系统 | Windows 10 或 Windows 11，64 位 |
| CPU | 4 核及以上 |
| 内存 | 16 GB 及以上，完整重跑建议保留更多空闲内存 |
| 磁盘 | 至少 10 GB 可用空间 |
| Python | 3.11 或更高版本 |
| GPU | 不需要 |
| 浏览器 | Edge、Chrome 或其他现代浏览器 |
| 网络 | 首次安装依赖时通常需要；系统运行和分析可在本地完成 |

### 4.2 权限要求

- 用户需要对项目目录具有读取和写入权限；
- 安装 Conda 或 Python 时可能需要管理员协助；
- 如果需要通过局域网供其他电脑访问，需要配置 Windows 防火墙；
- 风险排名、真实账户映射和案例材料应存放在受控目录中。

## 5. 四种部署方式

推荐优先级如下：

1. 已有 `jk_new` 环境：最快，适用于当前开发电脑；
2. 新建独立 Conda 环境：最适合甲方新电脑；
3. 普通 Python 虚拟环境：适合不能使用 Conda 的电脑；
4. Docker：适合已有 Docker 运维能力的环境。

## 6. 方式一：使用已有虚拟环境

### 6.1 打开命令行

在 Windows 开始菜单中打开“Anaconda Prompt”或“Miniconda Prompt”。

### 6.2 进入项目目录

请把下列占位符替换为项目解压后的实际目录：

```powershell
cd /d "<项目根目录>"
```

如果在 PowerShell 中运行，应使用：

```powershell
Set-Location "<项目根目录>"
```

### 6.3 激活环境并检查

```powershell
conda activate 虚拟环境名
python --version
python -c "import streamlit, pandas, sklearn; print('环境检查通过')"
```

Python 版本应为 3.11 或更高版本，最后一条命令应输出“环境检查通过”。

### 6.4 启动系统

可以直接双击项目根目录中的 `run_app.bat`，也可以在命令行执行：

```powershell
streamlit run app.py
```

浏览器通常会自动打开。若未自动打开，请访问：

```text
http://127.0.0.1:8501
```

## 7. 方式二：创建独立 Conda 环境

### 7.1 安装 Conda

电脑需要安装 Anaconda 或 Miniconda。安装完成后，重新打开 Anaconda Prompt 或 Miniconda Prompt，并执行：

```powershell
conda --version
```

能够显示版本号表示安装成功。

### 7.2 使用项目环境文件创建环境

进入项目根目录后执行：

```powershell
conda env create -f environment.yml
```

该命令会创建名为 `fraud_fund_graph` 的环境。完成后执行：

```powershell
conda activate fraud_fund_graph
python -m pip install -e . --no-build-isolation
```

如果环境已经存在，可更新环境：

```powershell
conda env update -n fraud_fund_graph -f environment.yml --prune
```

### 7.3 启动系统

交付的 `run_app.bat` 会先使用项目目录内的 `.venv`；如不存在，再尝试激活 `fraud_fund_graph`，最后兼容开发环境 `jk_new`。因此环境创建完成后可以直接双击启动，也可以执行：

```powershell
conda activate fraud_fund_graph
streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

启动脚本根据自身所在目录定位项目根目录，不包含开发电脑的绝对路径。

## 8. 方式三：使用普通 Python 虚拟环境

没有 Conda 时，可以使用 Python 自带虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install -e . --no-deps --no-build-isolation
streamlit run app.py
```

如果 PowerShell 提示禁止运行脚本，可使用命令提示符执行：

```bat
.venv\Scripts\activate.bat
```

或者由系统管理员按照单位安全策略调整 PowerShell 执行策略。

## 9. 方式四：Docker 部署

### 9.1 适用场景

Docker 适用于已经安装 Docker Desktop、希望隔离 Python 环境的电脑。当前镜像最适合启动交付包中已经生成好的界面和结果。

### 9.2 构建镜像

在项目根目录执行：

```powershell
docker build -t fraud-fund-graph:0.2.0 .
```

### 9.3 启动容器

```powershell
docker run --rm -p 8501:8501 fraud-fund-graph:0.2.0
```

访问：

```text
http://127.0.0.1:8501
```

按 `Ctrl+C` 停止容器。

### 9.4 Docker 注意事项

- Dockerfile 会复制界面运行需要的处理后数据、模型和已经生成的结果；
- `data/raw` 出于数据安全考虑被 `.dockerignore` 排除，不会写入镜像；
- 如果需要在容器中完整重跑，应把原始数据挂载到 `/app/data/raw`，项目配置无需写入宿主机绝对路径；
- 在生产或内网服务器部署前，应由运维人员补充访问控制、HTTPS、日志审计和数据备份方案。

在项目根目录依次执行：

```powershell
python --version
python scripts/verify_delivery.py
```

正常情况下应看到：

```text
DATA_CHECK=PASS
GRAPH_CHECK=PASS
MODEL_CHECK=PASS
LINK_CHECK=PASS
PATH_CHECK=PASS
REPORT_CHECK=PASS
DELIVERY_CHECK=PASS
```

如果只需要查看现有结果，全部检查均通过后即可启动界面，无须重新运行模型。`PATH_CHECK` 专门确认原始数据位于项目内部、配置采用相对路径，并扫描可执行脚本中的硬编码绝对路径。

## 11. 界面启动、停止与重启

### 11.1 启动

```powershell
streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

### 11.2 停止

回到启动界面的命令行窗口，按：

```text
Ctrl+C
```

关闭浏览器页面不会自动停止后台程序。

### 11.3 重启

先按 `Ctrl+C` 停止，再重新执行启动命令。

### 11.4 端口被占用

如果提示 8501 端口被占用，可以使用其他端口：

```powershell
streamlit run app.py --server.address 127.0.0.1 --server.port 8502
```

然后访问 `http://127.0.0.1:8502`。

## 12. 允许局域网其他电脑访问

默认 `127.0.0.1` 只允许本机访问。如确需在受控局域网内共享，可执行：

```powershell
streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

其他电脑通过以下地址访问：

```text
http://服务器IP地址:8501
```

还需要满足：

1. Windows 防火墙允许 TCP 8501 端口；
2. 服务器和访问电脑处于可互通的受控网络；
3. 单位安全策略允许该服务；
4. 不把端口直接暴露到互联网；
5. 对真实账户和交易数据实施访问控制。

Streamlit 原型自身没有完善的用户认证和权限系统。如需多人生产使用，应先完成正式系统化改造。

## 13. 六个页面的使用方法

### 13.1 风险总览

用于快速了解项目全局情况：

- 查看有效账户数、交易数、主模型指标和风险覆盖情况；
- 从重点风险账户中选择一个账户；
- 查看该账户的局部资金关系图；
- 查看风险等级、风险分、排名和主要风险因素；
- 下载对应的研判材料。

建议将该页面作为日常演示和研判入口。

### 13.2 风险账户

用于检索全量风险排名：

1. 输入账户编号或使用筛选条件；
2. 选择风险等级；
3. 调整最低风险分；
4. 查看筛选后的账户、风险分、排名和解释；
5. 按需要导出结果。

风险排名表示相对核查优先级，不表示账户已经被认定涉诈。

### 13.3 资金图谱

用于动态查看账户关系：

1. 选择中心账户；
2. 选择交易日期范围；
3. 设置最小或最大金额；
4. 选择双向、转入或转出；
5. 选择一至三跳范围；
6. 按风险等级过滤节点；
7. 点击“生成 / 刷新资金图谱”；
8. 等待进度提示完成后，查看节点、边和动态路径的详细信息。

完整日期和金额范围会优先复用预聚合关系图；自定义条件会动态筛选交易并聚合。相同查询可以命中本地缓存。图中关系来自当前交易数据，不包含设备、电话、IP、工商关系或外部案件关系。

### 13.4 可疑路径

用于查看一至三跳资金路径：

- 选择锚点账户；
- 查看路径经过的账户；
- 查看路径交易笔数、累计金额和最近交易时间；
- 查看关系得分和证据摘要；
- 下载可疑路径表供后续核查。

路径越短、金额越大、交易越频繁，通常越值得优先人工核查，但仍需业务证据支持。

### 13.5 典型案例

系统提供五个典型案例。每个案例可以查看：

- 账户画像；
- 风险分、风险等级和排名；
- 关键交易；
- 主要关联账户；
- 可疑路径；
- 资金关系子图；
- 研判结论和建议核查事项。

也可以直接打开 `outputs/investigation_reports/五个典型案例研判材料.zip`，将案例材料整体交付或归档。

### 13.6 模型与口径

用于向甲方解释：

- 正式主模型如何选择；
- ROC-AUC、PR-AUC 和 Top 5% 召回的含义；
- 与规则基线相比的绝对提升、百分点变化和相对提升；
- 不同数据划分、观察截止、类别权重和参数下的稳定性；
- 标签确认时间缺失和嫌疑人样本较少等限制。

辅助模型指标不能替代嫌疑人主模型指标。

## 14. 使用新数据重新运行完整流程

只有在更换原始数据、修改配置或需要重新生成全部结果时，才需要执行本节。

### 14.1 备份当前结果

建议先备份：

- `models/`；
- `outputs/`；
- `reports/`；
- `logs/`；
- `MANIFEST.json`。

### 14.2 放置新数据

将新的：

- `账户表.xlsx`；
- `交易边表.xlsx`；
- `风险标签表.xlsx`；
- `说明.txt`；

放入项目内的 `data/raw`。不要直接覆盖旧数据，除非已经完成归档。配置中的默认相对路径为：

```yaml
paths:
  accounts: data/raw/账户表.xlsx
  edges: data/raw/交易边表.xlsx
  labels: data/raw/风险标签表.xlsx
  data_note: data/raw/说明.txt
```

### 14.3 核对字段

默认字段映射在 `configs/data_config.yaml`。如果新 Excel 的列名变化，必须先修改配置，否则数据准备阶段会失败。

### 14.4 修改观察截止时间

如数据周期变化，应修改 `configs/data_config.yaml` 中：

```yaml
time:
  feature_cutoff: "新的观察截止时间"
  label_as_of: "新的标签状态时间"
```

不能只替换数据而继续沿用错误的截止时间。

### 14.5 运行完整流水线

```powershell
python scripts/run_all_pipeline.py
```

流水线会依次完成：

1. 原始数据校验和标准化；
2. 时间截断、账户划分和特征工程；
3. 主模型、辅助模型和规则基线训练评估；
4. 资金图谱、关联账户和可疑路径分析；
5. 稳健性实验；
6. 项目报告和案例生成；
7. 界面专用数据生成；
8. 交付完整性检查。

运行日志保存在 `logs/pipeline_日期_时间.log`。出现错误时，应优先查看最后一个 `START` 但没有对应 `PASS` 的阶段。

### 14.6 刷新盲审材料

模型和链路结果更新后执行：

```powershell
python scripts/10_prepare_manual_review.py
```

该命令刷新匿名样本、内部映射和机器可读模板。项目已交付现成的 Excel 盲审表；如需重新构建 Excel 文件，应由具备 Node.js 和项目开发环境的技术人员运行 `review_tools/build_manual_review_workbook.mjs`。

## 15. 单独运行某一阶段

如完整流程中途失败，可以在问题修复后从对应阶段单独运行：

| 脚本 | 功能 |
|---|---|
| `01_prepare_data.py` | 数据读取、校验、清洗和账户划分。 |
| `02_build_features.py` | 行为、时间、金额和图谱特征。 |
| `03_train_evaluate.py` | 模型训练、评估、校准和全量评分。 |
| `04_link_analysis.py` | 关联账户、可疑路径和异常模式。 |
| `05_robustness_experiments.py` | 基础稳健性与消融实验。 |
| `06_generate_reports.py` | 核心报告、基础案例和文档。 |
| `07_extended_stability.py` | 扩展稳健性实验。 |
| `08_enhance_cases.py` | 五个案例的增强材料。 |
| `09_prepare_ui_data.py` | 交互界面专用关系数据。 |
| `10_prepare_manual_review.py` | 甲方盲审数据准备。 |

例如：

```powershell
python scripts/09_prepare_ui_data.py
```

阶段之间存在依赖关系。首次部署或数据完全更新时，应优先运行 `run_all_pipeline.py`，不要随意跳过前置阶段。

## 16. 甲方关联链路盲审

### 16.1 文件位置

```text
outputs\manual_review\链路盲审表.xlsx
```

### 16.2 审核流程

1. 将盲审工作簿复制给两名业务审核人员；
2. 审核人员 A 和 B 分别填写对应席位；
3. 只依据匿名证据评价，不查看真实账户映射；
4. 使用下拉选项填写解释合理性、核查价值和证据充分性；
5. 对“不合理”或“证据不足”补充原因；
6. 审核完成后保存工作簿；
7. 将回填文件放回原位置或在汇总命令中指定路径。

### 16.3 汇总盲审结果

默认文件位置不变时执行：

```powershell
python scripts/aggregate_manual_review.py
```

指定其他工作簿时执行：

```powershell
python scripts/aggregate_manual_review.py "<已回填盲审表的完整路径>"
```

汇总结果写入：

- `outputs/manual_review/manual_review_summary.json`；
- `outputs/manual_review/manual_review_responses.csv`；
- `reports/07_client_manual_review_report.md`。

`blind_review_key.csv` 包含匿名编号到真实账户的映射，应由项目管理人员单独保管，不应在盲审阶段交给审核人员。

## 19. 常见问题处理

### 19.1 提示“conda 不是内部或外部命令”

原因：Conda 未安装，或当前终端未加载 Conda。

处理：

- 使用 Anaconda Prompt 或 Miniconda Prompt；
- 重新安装或初始化 Conda；
- 或改用第 8 节的 Python 虚拟环境方式。

### 19.2 提示找不到 `jk_new`

原因：甲方电脑没有开发环境中的 `jk_new`。

处理：使用 `conda env create -f environment.yml` 创建 `fraud_fund_graph`。新版 `run_app.bat` 会自动优先使用该环境。

### 19.3 提示缺少 Python 模块

例如：`ModuleNotFoundError: No module named 'streamlit'`。

处理：

```powershell
python -m pip install -r requirements.txt
```

并确认执行安装和启动时使用的是同一个 Conda 环境。

### 19.4 浏览器显示无法访问

检查：

1. 启动命令窗口是否仍在运行；
2. 地址是否为 `http://127.0.0.1:8501`；
3. 8501 端口是否被占用；
4. 是否在服务器上启动却在另一台电脑输入了 `127.0.0.1`；
5. Windows 防火墙是否阻止局域网访问。

### 19.5 界面提示结果文件不存在

原因：`data/processed`、`models/final` 或 `outputs` 不完整。

处理：先执行：

```powershell
python scripts/verify_delivery.py
```

如果检查失败且原始数据齐全，再执行完整流水线。

### 19.6 完整流程提示找不到 Excel

确认四个原始文件位于项目内的 `data/raw`，且名称与 `configs/data_config.yaml` 一致。无需修改为甲方电脑上的绝对路径；如自行在命令行传入带空格的文件路径，请保留引号。

### 19.7 完整流程运行较慢

交易数据约 90 万条，特征、图谱和扩展稳健性实验需要一定时间。请保持命令窗口开启，不要因短时间没有新输出就强制关闭。可通过任务管理器确认 Python 仍在使用 CPU 或内存。

### 19.8 内存不足或程序被系统终止

关闭 Excel、浏览器多余标签页和其他占用内存的程序；确认使用 64 位 Python；完整重跑建议在 16 GB 以上内存的电脑执行。

### 19.9 安装依赖时网络失败

确认电脑能够访问单位允许的 Python 包源；必要时由管理员配置代理或内部镜像。已安装好依赖后，系统日常使用不需要访问外部服务。

### 19.10 端口冲突

改用 8502 或其他允许端口，并在浏览器地址中使用相同端口。

### 19.11 页面数据没有更新

更换数据后必须重新运行完整流水线，并重启 Streamlit。仅刷新浏览器不会重新训练模型或生成路径。

### 19.12 Excel 盲审表显示公式未更新

使用 Microsoft Excel 打开并允许自动计算，完成填写后保存。如果单位 Excel 设置为手动计算，可在“公式”中执行“立即计算”。

## 20. 数据安全与运维建议

1. 原始 Excel、风险账户排名、案例报告和真实映射文件应限制访问；
2. 不要将系统直接暴露到互联网；
3. 对外演示优先使用匿名化或脱敏材料；
4. 每次更换数据前备份上一版本的 `models`、`outputs`、`reports` 和日志；
5. 使用 `MANIFEST.json` 核验交付文件完整性；
6. 对盲审映射 `blind_review_key.csv` 单独授权；
7. 生产化前补充登录认证、角色权限、操作审计、加密、备份、监控和容灾；
8. 不把模型高风险结果直接作为自动处置依据。

## 21. 日常使用建议流程

业务人员每天或每批次数据的推荐使用顺序：

1. 管理员确认系统和结果版本；
2. 启动 Streamlit；
3. 在风险总览查看总体变化；
4. 在风险账户页确定优先核查对象；
5. 在资金图谱页理解账户关系；
6. 在可疑路径页核对资金传导；
7. 查看或导出典型案例材料；
8. 记录人工核查结论；
9. 定期汇总误报、漏报和无法判断原因；
10. 获得新标签确认时间或处置结果后，再组织模型复评。

## 22. 最简操作清单

对于已经准备好环境和结果文件的电脑，只需：

```powershell
cd /d "<项目根目录>"
conda activate fraud_fund_graph
python scripts/verify_delivery.py
streamlit run app.py
```

浏览器访问 `http://127.0.0.1:8501`。使用结束后回到命令窗口按 `Ctrl+C`。

如果使用当前开发电脑的既有环境，也可以把第二行替换为：

```powershell
conda activate jk_new
```
